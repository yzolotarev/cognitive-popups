# Cognitive Popups v2

The v2 core implements the reading loop without coupling state to a GUI. A resident
watcher precomputes cues from the primary selection; the hotkey only reads the
RAM cache and commits the selected fragment to the common buffer:

```text
primary selection -> precompute 4 cues -> hotkey -> flash -> common buffer -> Feynman check -> 1-2 gaps
```

The common buffer survives Feynman checks. It is cleared only by an explicit
`clear_buffer()` action; the cleared session can be archived in history.

## Prediction step after the map (optional; implemented)

After one or more four-cue fragments have been collected and arranged into a mind map, the reader can optionally write one concrete sentence about a relation between the map's objects. This sentence is
the prediction, not the prediction error itself:

```text
map -> reader's one-sentence hypothesis -> comparison with the source
   -> mismatch between hypothesis and source = prediction error
```

The sentence should be a commitment that can be confirmed, partially confirmed, or
rejected. It is not a summary or a definition. The important part is that the reader
writes it before checking the source, so the map becomes an active model rather than
a passive list of recognized terms. The current digital version exposes this as an
optional `Моя гипотеза` menu action; it does not attempt to capture or parse the mind
map itself.

## Module map

The reading loop:

- `models.py` — fragments, sessions, Feynman checks, hypotheses;
- `prompts.py` — one strict prompt contract per action;
- `prompt_settings.py` — local overrides, re-read from disk on every call;
- `client.py` — the OpenAI-compatible client every call goes through;
- `service.py` — application flow, independent of GTK and hotkeys;
- `desktop.py` — GTK surfaces, hotkey signals and the busy guard;
- `popup_helper.py` — the packaged popup renderer, and the only component
  that reports clicks.

Durable state, one store per kind:

- `records.py` — the reading ledger: sessions, fragments, hypotheses, checks, goals, tasks;
- `notes.py` — the reader's own notes about a misreading;
- `history.py` — explicitly archived buffers;
- `event_log.py` — append-only telemetry.

Practice:

- `nodes.py` — cuts a fragment into study nodes (definition, method, proof,
  example, application, exercise), so a task targets one concrete move;
- `tasks.py` — generates a task and its solution separately, checks the answer,
  runs the practice window and the revisit path;
- `verify.py` — checks that a task is answerable before it is shown, and checks a
  reader's attempt;
- `practice.py` — prepares one task in the background from one exact snapshot.

Side panel:

- `hud.py` the panel itself, `hud_state.py` what it may show, `hud_ipc.py` the
  Unix socket it asks the daemon over.

Support: `goals.py` (the goal bookmark), `observation.py` (passive presentation
records), `request_gate.py` (background work yields to a waiting reader),
`operation_context.py` (one operation across callbacks), `__main__.py` (entry point).

## Launcher actions

`scripts/cognitive-popups-signal.sh` takes exactly one action name:

```text
seed | feynman | prediction | note | clarify | summary | reframe
     | reframe-ask | keys | intent | example | example-ask | stop
```

`scripts/cognitive-tasks.sh` generates a task (`--menu`), attempts the last one
(`--practice [TASK_ID]`), lists archived material (`--revisit`) or picks from it
(`--revisit-menu`). `scripts/cognitive-hud.sh` starts or toggles the panel.

| Key | Action |
|---|---|
| `Alt+W` | `seed` — four cues from the primary selection |
| `Alt+F` | `feynman` — check the current buffer by explanation |
| `Alt+R` | `reframe` — one alternative view of the same material |
| `Alt+Shift+R` | `reframe-ask` — the same, with the reader's own question |
| `Alt+E` | `note` — a note anchored to the selection |
| `Alt+C` | `clarify` — explain terms, or ask a free-form question |
| `Ctrl+Q` | `summary` — compress the selection to its gist |
| `Alt+I` | `intent` — the goal bookmark |
| `Alt+G` | `example`; `Alt+Shift+G` adds an explicit request |
| `Alt+T` | the task menu; `Alt+Shift+T` revisits archived material; `Alt+Y` attempts the last task |
| `Alt+H` | show or hide the side panel |
| `Alt+K` | `keys` — the shortcut reference |

The hypothesis check (`prediction`) has no default key: it is reachable from the
panel's "…" menu, together with the Feynman dialog and the other modes. No action
shows a key it does not perform — where a click opens one specific task rather than
the latest one, the panel says so instead of showing `Alt+Y`. `Alt+K` lists the same
set from a table held in memory: it asks the model for nothing, writes nothing to
the ledger, and the entry for an action without a key says where that action lives
instead of naming a combination that is never bound.

## Practice tasks

A task is generated from the material, shown as a condition, and answered by the
reader before any solution appears: the condition and the solution are two separate
prompt calls, because bundling them would turn every exercise into a worked example.
The answer is checked locally where it can be (arithmetic on a computational
template), otherwise against the source, and only then by stated confidence.

Quoted support (`grounding`) must be found verbatim in the material. A claim that
is not there is marked, not silently accepted; a task whose support cannot be found
is refused rather than shown.

Practice stays opt-in. The panel highlights a saved task because the task exists,
not because the reader is ready; dismissing the highlight does not offer the next
one, and no task is ever proposed on a timer.

## Background preparation

With the reader's explicit permission (`prepare_in_background`, off by default), the
panel may prepare **one** task from one saved snapshot while they read. The four
segments above the button are the completed steps of that preparation — material
accepted, application found, condition obtained, check passed — not a percentage of
understanding. A manual request always goes first.

## Reframing

`Alt+R` generates straight away: pressing the key is the whole request. The material
is the live selection, or the exact fragments of the last hypothesis; the focus is
that hypothesis, or the accepted goal, and when there is neither the model picks the
organising principle itself — an empty focus is a case of its own in the prompt, not
a missing argument. `Alt+Shift+R` opens the field for a reader who wants to steer the
frame in their own words.

What comes back is labelled as the model's suggestion, carries a verbatim quotation
from the supplied snapshot, and is refused outright when the material does not
support a proposal. The reader's own structure is never overwritten with it, and no
window opens on its own after a failed hypothesis — the result window offers the
action, and closing it is a complete answer.

## Revisiting earlier material

`--revisit` lists source snapshots from closed sessions, with the hypotheses that
point at each one; `--revisit-menu` turns that list into a keyboard menu. A chosen
snapshot produces one new application task, and the stored hypothesis travels as the
reader's own question — never as evidence, and never as a claim about their
knowledge. There is no schedule, no reminder and no ranking by how a hypothesis was
judged: a verdict is not a readiness signal.

## Desktop prototype

Start the resident UI from the repository root:

```bash
PYTHONPATH=src python3 -m cognitive_popups
```

Signals for the existing Hyprland binding style:

```text
SIGUSR1  -> four-cue seed from the current selection
SIGUSR2  -> Feynman check for the current buffer
SIGHUP   -> check one written hypothesis against the source
SIGWINCH -> take the queued request (note, clarify, summary, reframe,
            intent, example) or open the mode menu
SIGTERM  -> stop
```

`GLib.unix_signal_add` accepts exactly six signals and this daemon already uses
them all, so the actions without one of their own leave their name in
`$COGNITIVE_STATE_DIR/request` and wake the loop with `SIGWINCH`.

### Where the selected text comes from

`selected_text()` probes sources in a fixed order and returns the first non-empty one:

```text
primary (wayland: wl-paste --primary)
  -> primary (x11: xclip -selection primary)
  -> clipboard (wayland, then x11)
```

Under XWayland the two primary selections live in separate namespaces: neither tool can
read the other's. That makes a stale X11 owner shadow the clipboard. While an orphaned
`xclip -selection primary` owns the selection, the X11 probe succeeds with a constant
string, the clipboard is never consulted, and every hotkey press yields the same four
cues no matter what was selected. This is not a model or prompt failure, and restarting
the service does not clear it: the owner is a foreign process.

Diagnose with:

```bash
COGNITIVE_DEBUG=1 PYTHONPATH=src python3 -m cognitive_popups --diagnose
```

`--diagnose` prints what each source returns right now. Non-empty `primary-x11` while the
Wayland primary is empty is the signature; confirm the owner with `pgrep -af 'xclip|wl-copy'`
and stop it.

All v2 UI surfaces are compact utility popups rather than full application windows:
cue flash, Feynman dialog, and the buffer/history panel. They stay floating and
out of taskbar/alt-tab where the window manager permits it.

The cue popup discloses its columns one layer at a time. The first column shows the
four `simple` words; clicking one opens that word's short `meaning` in the second
column, and clicking the meaning reveals the exact `term` in the third. The terms
are never handed over all four at once, and each revealed row keeps the place of the
word it belongs to.

### Cue popup layers

```text
layer 1  simple words        клик по слову
layer 2  short meaning       клик по строке смысла
layer 3  exact term          клик — показать/скрыть
```

The prototype stores archived sessions at
`~/.local/state/cognitive-popups/history.json`. The current buffer is kept
in RAM and is archived only by the explicit Clear button.

## Interaction log (SQLite)

Every window and every click is recorded in
`~/.local/state/cognitive-popups/events.sqlite3`, so a reading session can be
reconstructed after the fact: which hotkey fired, what the popup showed, which
cue was clicked, which layer that opened, and how long the window stayed up.

```text
19:11:14.235  hotkey       desktop  seed  4 слова
19:11:14.236  └ window_spawn desktop  dual  4 cues
19:11:14.285    └ window_open  popup    dual  L1  4 cues
19:11:14.285      └ click        popup    dual  L1  #4  «chunking»
19:11:14.285        └ layer_open   popup    dual  L2  #4  «chunking»  word revealed
```

Read it back with:

```bash
PYTHONPATH=src python3 -m cognitive_popups.event_log --tail 40
PYTHONPATH=src python3 -m cognitive_popups.event_log --session <id> --json
PYTHONPATH=src python3 -m cognitive_popups.event_log --prune-days 30   # telemetry only
```

Rows are grouped by `session_id` (one hotkey press and everything it caused)
and chained by `parent_id`, so the indentation is causality rather than merely
order. The popup runs as its own process; the link survives that boundary
through `COGNITIVE_EVENT_SESSION` and `COGNITIVE_EVENT_PARENT` in its
environment.

| Field | Meaning |
|---|---|
| `event` | `hotkey`, `window_spawn`, `window_open`, `click`, `layer_open`, `layer_toggle`, `window_close`, `result`, `error` |
| `window` | `seed`, `dual`, `menu`, `input`, `text`, `objects`, `panel`, `feynman`, `prediction` |
| `layer`, `item_index`, `item_label` | which column of the dual popup and which cue was clicked |
| `source_hash`, `fragment_id` | the fragment a seed belongs to |

Timings are stored twice: `ts_utc` (UTC, milliseconds, for reading) and
`ts_epoch` (the same instant as a float, for ordering and intervals).

Three things worth knowing:

- the log holds cue words and window titles, that is fragments of what you were
  reading. `COGNITIVE_EVENT_DISABLE=1` turns it off, `COGNITIVE_EVENT_DB` moves it;
- logging never blocks or breaks a popup: an unavailable database loses events
  instead of failing the interaction. Telemetry is disposable, so `--prune-days N`
  trims it; error notes are never expired automatically;
- `popup_helper.py` is the packaged renderer and the only component that reports
  clicks. Setting `COGNITIVE_POPUP_HELPER` pins an external renderer again; that
  renderer logs nothing.

## Notes

A note gives a misreading a home. When a phrase trips the reader up — `working
memory` read as a decorative description rather than the name of a standard — the
note records what they thought and why, so the gap can be closed later instead of
forgotten. It is their own account, not a verdict about what they know, so the popup
says only that the note was saved.

```text
Alt+E -> выделить фразу -> окно заметки (многострочное) -> записано
```

The note owns its anchor text. Sessions live in RAM and reach disk only through an
explicit Clear, so a fragment a note points at may never be stored: the anchor has
to stand on its own months later. `anchor_key` is the same text folded for lookup.

```bash
PYTHONPATH=src python3 -m cognitive_popups.notes --open
PYTHONPATH=src python3 -m cognitive_popups.notes --repeats   # один якорь N раз = настоящая дыра
PYTHONPATH=src python3 -m cognitive_popups.notes --by-kind
PYTHONPATH=src python3 -m cognitive_popups.notes --close 7 -m "worked through the definition"
PYTHONPATH=src python3 -m cognitive_popups.notes --delete 7
```

| Field | Meaning |
|---|---|
| `anchor`, `anchor_key` | the phrase as captured, and its folded lookup form |
| `comment` | the reader's own words |
| `kind` | optional category; not asked for at capture time yet |
| `status`, `closed_utc`, `resolution` | open to closed, with what was done about it |
| `fragment_id`, `source_hash` | the buffer fragment that was open, when there was one |

Notes live in `~/.local/state/cognitive-popups/notes.sqlite3`, a separate file
from the event log: telemetry and the reader's own words have different lifetimes
and different tolerance for failure. Unlike the log, this store never fails
silently — `add()` raises and the popup says so, because a lost note is worse
than a lost event.

The store predates the current wording, and older text calls these "error notes".
The name is historical: nothing classifies a note as a mistake, and no category is
asked for at capture time, because that choice would stand between a thought and
recording it.

`Alt+E` reaches the desktop layer through `scripts/cognitive-popups-signal.sh`.
There is no signal left to give it: `GLib.unix_signal_add` accepts exactly six
(`HUP`, `INT`, `TERM`, `USR1`, `USR2`, `WINCH`) and this daemon already uses all of
them, so `note` leaves its action in `$COGNITIVE_STATE_DIR/request` and wakes the
loop with `SIGWINCH`. `SIGQUIT` was tried first and silently failed: GLib refused
the assertion, no handler was installed, and the default disposition would have
killed the daemon. Add the binding to your Hyprland config:

```lua
hl.bind("ALT + E", hl.dsp.exec_cmd(signal .. " note"))
```
