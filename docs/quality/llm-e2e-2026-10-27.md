# Real model requests on every LLM surface — 2026-10-27

Environment: Arch Linux + Hyprland 0.56, `implementation/full-v1`, release
build. Provider: OpenAI-compatible chat-completions endpoint
`https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`,
models `gemini-3.5-flash` (first 10 answers) and `gemini-flash-lite-latest`
(remaining 7 after the free-tier per-model quota was exhausted, see below).
The API key lived only in the system credential store (`keyring` entry
`default|<endpoint>`); it never appeared in SQLite, logs, screenshots or the
repository (checked by searching both databases, the state directory, the git
index and the run logs for a key prefix; all clean).

Method: every surface was opened on the live desktop with
`--manual-source` (material on stdin), the request was triggered **only** by the
explicit button, and the result was read from the window screenshot plus the
event journal and the workspace database. No mocks were used except where a
row says so.

Content check (not just "non-empty"): every answer was read and compared with the
material it was given.

- Four Words produced anchors that were specific to the material (margin:
  «доля от выручки / маржа / процент от продаж»; Bayes: prior, likelihood,
  posterior; Git: «указатель», «маяк», «разработка», «навигация»), not generic
  four-word summaries, and the disclosure layers differed per anchor.
- The task exercises asked about the material without printing the answer.
- Feedback on the answer «около 6 лет» for the rule of 72 named the arithmetic
  (72/8 = 9), named the conceptual error (simple vs compound interest) and gave
  suggestions; the answer itself stayed stored verbatim as `user_text`.
- The prediction comparison split «исходная гипотеза» from «что подтверждает
  источник» and marked the 80/20 claim as an empirical regularity, correcting
  the reader's "mathematically proven" hypothesis.
- Session plans changed with the subject (margin: margin/markup formulas;
  photoelectric: photon energy vs intensity), kept `[x]` unchecked, and were
  saved as drafts, not started.
- The context answers addressed the exact question (why a moved tag breaks
  published meaning while a moved branch does not; why intensity does not raise
  the maximum kinetic energy).

Authorship stayed separated in the journal: `ai|ai_response` (17 events),
`user|user_text` (10), `system|source`. After all runs `reviews` = 0 and
`schedules` = 0: no model answer wrote FSRS state.

## Failure handling

| Scenario | How it was produced | What the window showed | Verdict |
|---|---|---|---|
| No key | credential deleted from the store | «В системном хранилище нет ключа API. Откройте настройки и добавьте ключ.»; input kept, no request sent | PASS |
| Rejected key | bogus key stored | «Провайдер вернул HTTP 400. Тело ответа скрыто для приватности.»; input kept | PASS |
| Malformed 200 | loopback HTTP server returning `this is not json at all` | «Провайдер вернул пустой, повреждённый или слишком большой ответ.»; input kept | PASS |
| Timeout | `gemini-3-flash-preview` on a planning-shaped prompt (no answer in 60 s) | «Запрос к провайдеру не удался или истёк по времени. Сохранённый ввод не изменён.» after the 60 s limit | PASS |
| Real 503 | provider high demand | «Провайдер вернул HTTP 503. Тело ответа скрыто для приватности.» | PASS |
| Real 429 | free-tier quota exhausted | «Провайдер вернул HTTP 429. Тело ответа скрыто для приватности.» | PASS |

In every case the process stayed in its event loop, the material and the typed
answer were still in the window, and retrying after the cause was removed
worked. There is no silent retry: each retry was a second explicit button press.

## Defects found by this run and fixed

1. **Model answers in a Markdown fence were rejected.** The first real Four
   Words answer arrived as ```` ```json … ``` ```` and the window said
   «invalid stored data» while a 732-character answer sat in the journal. Added
   `services::json::extract` (fence/prose unwrapping, still strictly typed) and
   used it for Four Words, task exercises and session plans; schema errors now
   say so instead of «invalid stored data».
2. **A key with a trailing line break was reported as a network failure.** The
   entry stored from a file kept its `\n`, the HTTP builder rejected the header
   and the window said «request failed or timed out». Keys are now trimmed on
   save and validated before any networking (`ProviderError::InvalidKey`).
3. **The session window could not open.** `InstanceGuard` did not know the
   `session` surface, so `cognitive-popups session` exited with «invalid
   instance lock». The surface list is now a constant (`INSTANCE_WINDOWS`) with
   a test.
4. **The session plan pushed the action row out of the window.** A long plan
   grew the scroll area without bound and the buttons fell outside the window.
   The plan now scrolls inside a bounded, clipped area; the FSRS note and the
   provider route are visible without scrolling.
5. **A generated session plan was saved but not opened.** The newest draft was
   hidden in the picker. A freshly generated draft now opens under the timer
   (`pending-session`), with a test.
6. **The exercise criterion was shown before the attempt** — and the model had
   written the answer into it («делением 72 на 8, что равно 9 годам»). The
   criterion is now hidden until the answer is frozen, then shown for the
   comparison.
7. **Hand-typed material was labelled as a clipboard fallback.** The Four Words
   window called every non-selection source «Clipboard fallback: давность и
   источник не подтверждены», including stdin input. Provenance now comes from
   one function (`text::provenance`) with the three real kinds; a manual
   fragment reads «ввод вручную (явно предоставленный текст)».
8. **English errors in a Russian UI.** Provider and capture errors were
   English (`Provider returned HTTP 429…`, `cannot read the clipboard…`). All
   user-facing strings are Russian now.
9. **Raw Markdown in feedback.** `**…**`, `###` and bullets rendered literally
   in the feedback field. The display copy is flattened (`text::plain`), the
   journal keeps the model's text unchanged.

## Not verified in this run (BLOCKED or out of reach)

- **Second full sweep with `gemini-3.5-flash`.** The free tier allows 20
  requests/day per model; that bucket was exhausted mid-run (the provider
  answered `429 … limit: 20, model: gemini-3.6-flash … retry in 19h57m`). The
  remaining inputs were run with `gemini-flash-lite-latest`, which is what the
  journal records for those answers. A repeat with the original model is
  blocked until the quota resets.
- **Slow thinking models.** `gemini-3-flash-preview` did not answer a plan-style
  prompt inside the 60 s limit; that is why the timeout row above exists. The
  product's 60 s cut-off suits flash-class models, not slow reasoning models.
- **Windows desktop, real browser/PDF capture, Hyprland global hotkeys** — not
  part of this run (see `desktop-evidence-2026-10-27.md`).

## Test data left behind

The runs wrote real records into
`~/.local/state/cognitive-exoskeleton-v1/`: sources and model answers in
`journal.sqlite3`, one subject (renamed to «Физика: фотоэффект» for the second
plan), two AI session drafts and two committed task attempts in
`workspace.sqlite3`. They are inspectable in the product (history, sessions) and
can be deleted by the author; nothing was auto-deleted by the tests.

## Key handling

The key was pasted in chat before this run, so it must be treated as exposed:
rotate it in the provider console. It lives only in the system keyring on this
machine and in a `600` temporary file that was removed at the end of the run.
