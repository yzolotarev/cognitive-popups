# Cognitive Popups v2 — спецификация для разработки

Версия: 28.10.2026. Единый документ для разработчика или агента на ПК владельца.

**Приоритет источников при противоречии:**
1. `docs/v2/decisions.md` — решения владельца и делегированные решения, B1–B35;
2. этот документ;
3. `docs/v2/function-map.md` — подробная карта 101 функции v1 с примерами и крайними случаями;
4. IDEAL STATE от 27.10;
5. спецификация v0.2 из Rust-репозитория (сверка — `docs/v2/reconcile-rust-spec.md`).

Ссылки вида (B27), (F-19), (Q-31) ведут в эти документы.

---

## 1. Продукт

Слой горячих клавиш поверх любой программы, где человек учится: браузер, PDF, редактор, тренажёр. Помогает понять текст, отрабатывать операции, проверять себя и организовывать короткие учебные шаги.

**Главная формула** (владелец, 14.10; B4): *уменьшать стоимость организации обучения, а не стоимость самостоятельного мышления.*

**Три принципа, которые действуют во всех функциях:**
1. **Сначала своя попытка, потом помощь или ответ** (Янг; B8, B19).
2. **Правила задаются заранее в коде; LLM только применяет их к переданным данным, ссылается на реальные события и никогда не ставит оценок** (B21, B27).
3. **Незаметна, когда человек знает, что делает; понятна, когда ему нужна помощь** (Apple HIG; B14–B19).

## 2. Стек и платформа (B35)

- **Rust + GTK 4 (`gtk4-rs`) + `gtk4-layer-shell`.** Продолжается репозиторий `yzolotarev/cognitive-popups`: журнал событий и доменная модель уже есть.
- **Первая платформа — Hyprland (Wayland).** Windows отложен (B1). Модуль захвата и окон отделён от учебной логики.
- **Память:** crate `fsrs` (fsrs-rs, open-spaced-repetition).
- **Формулы:** модель пишет Unicode-нотацию (F-62); отрисовка — typst как библиотека (проверить на шаге P0) или другой локальный рендер. Если формулу нарисовать не удалось, показывается текст.
- **Промпты — файлы данных** (`prompts/*.md` или JSON), правятся без пересборки. Исходники для переноса: `docs/v2/port/prompts/`.
- **Анализ и эксперименты** (MRT, оценка промптов) — отдельные Python-скрипты над той же SQLite, не внутри приложения.
- **Откат:** если проба P0 не проходит критерии (`docs/v2/ROADMAP.md`), разработка идёт на Python, развитием v1 (прежнее B2).

## 3. Инварианты (критерии приёмки для всех систем)

INV-01…INV-09 взяты из Rust-спеки v0.2 (B34); INV-10…INV-13 — решения 28.10.

| ID | Инвариант |
|---|---|
| INV-01 | Исходный текст, мысль пользователя и текст ИИ хранятся раздельно и не подменяют друг друга |
| INV-02 | «Завершил шаг» и «освоил» не создают FSRS `Good` и review (A7) |
| INV-03 | Любой вывод LLM о навыке ссылается на существующие события; несуществующая ссылка отбрасывается кодом |
| INV-04 | Повтор события, двойной клик или повторная доставка не создают лишний review |
| INV-05 | «Верно после помощи», «не знаю», «заблокировано», «ошибка» и «успех» — разные состояния |
| INV-06 | «Отложено» или «не актуально» ≠ «забыл»; не портит FSRS |
| INV-07 | Комплексный ответ не обновляет слепо все составляющие единицы |
| INV-08 | Прерванный Alt+I восстанавливается без фальшивого завершения |
| INV-09 | Без явного согласия нет фоновой записи и инициативных окон |
| INV-10 | LLM никогда не ставит оценку FSRS и не помечает попытку как успех (B21, B27) |
| INV-11 | Вид следующего учебного действия выбирают правила (планировщик), а не LLM (B32) |
| INV-12 | Ничего необратимого автоматически: удаление, объединение, снятие цели — только действием пользователя и с откатом (HIG; B32) |
| INV-13 | Окно, открывшееся само, не забирает фокус клавиатуры; одновременно не больше одного такого окна (HIG; B15) |

## 4. Системы (порядок разработки — B10)

Каждая система — отдельный модуль (crate) со своими тестами и минимальной командой CLI. Её можно проверить без окон и без остальных систем. Формат: назначение → правила → интерфейс → приёмка.

### S1. Журнал событий

- **Назначение.** Записывать всё, что произошло; источник для учебных единиц, MRT, Alt+B.
- **Правила.**
  - Каждое событие: `event_id`, время (UTC и локальное), `operation_id` (F-100), вид, окно, `source` = `user` / `ai` / `other` (Q-30), полезная нагрузка, ключ идемпотентности (INV-04).
  - Текст из окон разработки (`origin=dev`, F-01) и из чатов с ИИ помечается и не участвует в учебной истории.
- **Интерфейс.**
  - `cp log add <json>`;
  - `cp log lesson <lesson_id>` → текст урока, где каждая запись начинается с `->user:`, `->ai generated for this task` или `sth else` (Q-30).
- **Приёмка.**
  - Если одно событие записать дважды с одним ключом, то в журнале одна запись.
  - Если выгрузить урок из 10 событий, то порядок и разметка источников совпадают с эталоном.

### S2. ИИ-клиент

- **Назначение.** Один вход ко всем моделям (F-63).
- **Правила.**
  1. Свой ключ (BYOK): Gemini и любой OpenAI-совместимый провайдер (A5, B2). Ключ хранится в Secret Service; если хранилища нет — файл с правами 600 и предупреждение (Q-69). Ключ, не прошедший проверку, сохранить можно, с предупреждением (Q-68).
  2. Модель Gemini по умолчанию — Flash-Lite текущего поколения (Q-67). Автоматического перехода на другого провайдера нет: при ошибке — понятный текст и [Открыть настройки ИИ] (Q-66).
  3. Ручной запрос всегда раньше фоновых; фоновые идут по одному; идущий фоновый запрос не прерывается (F-63).
  4. Ответ в JSON проверяется по схеме. Если не прошёл — 1 повтор с текстом ошибки.
  5. Без ключа работает всё, где ИИ не нужен (B18): Alt+E, Alt+I без генерации, «мои 4 слова» без сравнения, пробы с проверкой кодом из кэша, Alt+B, хаб.
  6. В настройках одна строка о передаче данных: «Выделенный текст и ваши записи из текущего окна отправляются провайдеру {имя}…» (B18).
- **Интерфейс.** `cp ai ask --prompt <key> --input <json>` → JSON.
- **Приёмка.**
  - Если ключа нет, то ни одного сетевого запроса.
  - Если идёт фоновый запрос, то ручной уходит без ожидания.

### S3. Учебные единицы

- **Назначение.** Превратить урок в единицы памяти (F-32; Q-30, Q-31, Q-43).
- **Когда.** В конце урока Alt+I. Учёба вне Alt+I в единицы не превращается (Q-30).
- **Вход промпта.**
  - выгрузка урока из S1 с разметкой источников;
  - реестр единиц текущего предмета: `id · название · проверяемое действие · вид`.
- **Выход (JSON):**
  ```json
  {"units":[{"title":"…","action":"проверяемое действие","kind":"execute|understand|select_method|contrast_methods|recall|transfer|speak|motor","events":["e12"],"same_as":"u17|null","why":"…"}],
   "merge_candidates":[{"unit_ids":["u3","u7"],"why":"…"}]}
  ```
- **Правила.**
  1. Сравнивать по проверяемому действию, а не по названию (Q-31; Янг, СМ гл. 7).
  2. Код проверяет `events` и `same_as`. Единица без существующих событий отбрасывается. Если `same_as` указывает на несуществующую единицу, единица считается новой.
  3. В единицы идут только те, где есть хотя бы одно событие `->user:`. Только прочитанное не считается (B35).
  4. Кандидаты на объединение — только среди единиц, которые все отмечены «освоил» (B32).
  5. Вид умения — один из 8 видов (B28).
- **Выход для пользователя.** Маленькое полупрозрачное уведомление «+1 новая · 2 добавлены к существующим». Висит, пока его не закроют, и не забирает фокус (B16). Если не закрыто, следующий урок обновляет то же уведомление. В хабе: «добавлено к «…» · [отделить]».
- **Интерфейс.** `cp units extract --lesson <id>` → JSON и запись.
- **Приёмка.**
  - Если ссылка на событие не существует, то единица не сохраняется.
  - Если урок содержит только события `ai` и `other`, то единиц нет.

### S4. Память (FSRS)

- **Назначение.** Когда и что повторять (B27, B30, B31, B32, B34).
- **Правила.**
  1. **Одно расписание — FSRS.** Отдельных лестниц (1/3/7/16/35) нет. Опровергнутые гипотезы и «вспомнить шаг» — тоже единицы FSRS (B32).
  2. **Что попадает:** всё важное (B27). На практике — единицы с событием пользователя, связанные с активной целью Alt+S.
  3. **Кто ставит оценку:**
     - код — где ответ проверяется программно (`verified`);
     - иначе пользователь, сверив свой ответ с эталоном после попытки: ✗ Промахнулся → Again, ½ Частично → Hard, ✓ Совпало → Good (`self_graded`);
     - Easy не ставится;
     - LLM — никогда (INV-10).
  4. **«Не помню» без попытки** → `self_report`; review не создаётся, единица остаётся в очереди (B34).
  5. **Сроки** считает FSRS: `desired_retention` = 0,9, одно на всё; `learning_steps` 1 мин и 10 мин; `relearning_steps` 10 мин. Ручного порога 24 ч нет (B30).
  6. **Параметры** (21 вес) — свои у каждого предмета Alt+S, когда по нему накопится история. До этого общие. Optimizer — раз в месяц (B32).
  7. **Дедлайн цели:** за 7 дней и меньше — профиль `short_deadline` (F-78): повторения других целей не предлагаются, но остаются в расписании. Отдельной «проверки перед дедлайном» нет (B30).
  8. **Цель снята** → её повторения на паузе, ничего не удаляется (Q-48).
  9. **Карточка по опровергнутой гипотезе** спрашивает, как на самом деле. Старая гипотеза показывается только после ответа (B32; Янг, СМ гл. 11).
  10. **Объединение единиц** (B32):
      - пользователь нажимает [Объединить] в хабе;
      - новая единица получает состояние FSRS самой слабой части;
      - части снимаются с расписания, не удаляются; [отделить] возвращает их состояния;
      - ошибка на объединённой → Again только ей, и она становится кандидатом в пробелы урока (INV-07);
      - «освоил» не наследуется.
  11. **Виды доказательств** (F-97 + B33): `independent_correct`, `correct_after_help`, `verified_incorrect`, `self_graded`, `model_verdict`, `self_report`, `skipped`, `no_data`. В FSRS идут только `independent_correct`, `correct_after_help`, `verified_incorrect` и `self_graded`.
- **Выход.** Пилюля «FSRS! N»: тихая, без звука, перетаскиваемая. Клик → Alt+T с категорией «Достань из памяти» первой (B31).
- **Интерфейс.** `cp memory due`, `cp memory review <unit> <again|hard|good> --source verified|self_graded`, `cp memory optimize --subject <id>`.
- **Приёмка.**
  - Если поставить «освоил», то review не создаётся.
  - Если ответ оценён моделью, то FSRS не меняется.
  - Если одну попытку отправить дважды, то review один.

### S5. Генератор практики (Alt+T)

- **Назначение.** «Муравьи», «тропинки», сборка и припоминание (F-18…F-24, F-19, F-22, F-79, F-96; B24, B31).
- **Правила.**
  1. **Пробы — основной режим:** дерево из 3 категорий × 3 карточки.
     - Категория — семейство операций с одним смыслом (invariant).
     - Карточка: действие, решённый образец «было → стало» (виден всегда), новая задача, скрытый ответ.
     - [Ещё 3] даёт 3 другие вариации той же категории, без ограничения.
     - Виды (живой контракт v1, B37): `numeric` — шаблон модели, случаи и ответы считает код; `drill` — 9 пар «вход → результат одного шага». У каждой ветви — дословная цитата из текста.
     - Контракт генерации — `docs/v2/port/prompts/NEW_probes_generate.md` (из `probe_generator__*.md`); проверяльщик — `NEW_probe_verify.md`. Контракт `probes__build_probe_prompt.md` с шестью видами в живом окне v1 не использовался.
  2. **Фильтр до показа** (F-96): арифметику проверяет код; нечисловые пары проверяет модель-проверяльщик — она только отсеивает, но не оценивает пользователя.
  3. **Отметки:** ✓/✗ до [Ответ] — самостоятельная попытка; после — «Совпало / Промахнулся».
  4. **Подсказка-кнопка по правилам** (F-19, `ProbeGuidance`):
     - первый промах → «другой вариант»;
     - второй промах → «Шаг поменьше»;
     - успех на новом случае → «Ещё 3»;
     - 3 чистые подряд → «Сложнее» (уровень +1, до 5; на 5-м — без подсветки, следующий шаг — [Собери вместе]); «Шаг поменьше» снижает уровень на 1 (B87).
  5. **Диагностика после промаха** (F-79): подшаг или новый случай той же операции; без модели.
  6. **«Достань из памяти»** (B31):
     - если у единиц подошёл срок FSRS, эта категория заменяет третью категорию из текста; клик по пилюле ставит её первой;
     - вопрос не берётся из текста на экране; эталон скрыт до ответа;
     - пользователь пишет ответ → [Ответ] (цитата из своих материалов) → Совпало / Частично / Промахнулся;
     - задачи с проверкой кодом (бывший Alt+V: `integer_roots`, `work_proportion`) — карточки этой категории.
  7. **[Собери вместе]** (B24): после 3 чистых вариаций в категории — одна целая задача на эти операции.
     - 10 типов — `docs/v2/port/prompts/tasks__types.md`.
     - Новичку в единице (нет ни одного самостоятельного верного ответа) — только типы 7–10 и 1.
     - Ручной вызов целой задачи — в ручном выборе Alt+T.
  8. **Тропинки** (F-22): «Выбор метода» и «Различи методы», проверка по критерию, заданному до ответа.
  9. **Маршруты Alt+T по весам v1** без «целой задачи» и «повторения», нормированные: пробы 70, выбор метода 5, Фейнман 5, гипотеза 3, продолжить задачу 2, старый материал 2, умение 2. Личный профиль может только выключить маршрут (Q-49). Хранилища трёх последних маршрутов и допуск «умения» — B64.
  10. **Подсказка-задание** (B19): постоянная строка с глаголом («Сделай 3 таких»). Пример — до первого завершённого действия, не чаще 1 в сутки; крестик убирает навсегда.
- **Интерфейс.** `cp practice probes --text <file>` → JSON проб; `cp practice whole --unit <id>`.
- **Приёмка.**
  - Если ответ `numeric` неверен по арифметике, то карточка не показывается.
  - Если нажать ✓ до [Ответ], то `attempt_before_reveal = true`.
  - Если пользователь новичок в единице, то типов 2–6 нет.

### S6. Захват текста

- **Назначение.** Текст выделения и его происхождение (F-01).
- **Правила.**
  1. Сначала primary selection; если пусто — эмуляция Ctrl+C с восстановлением буфера (только текст и картинки).
  2. Пароли из менеджера не захватываются.
  3. Происхождение: `primary` / `clipboard` / `copy` / `dev`. Чаты с ИИ (Claude, ChatGPT, Gemini…) помечаются.
  4. Лимит 12 000 символов.
  5. Кольцо недавних отрывков: до 12 за 30 мин; в промпт идут до 3 соседних (F-95).
- **Интерфейс.** `cp capture` → `{"text","origin","window_class","title"}`.
- **Приёмка.** Если выделить текст в kitty, то `origin = dev`. Если в буфере была картинка, то после захвата она там же.

### S7. Окна и демон

- **Демон.**
  - Один экземпляр; клавиша → действие.
  - Окна созданы заранее и только показываются: открытие < 100 мс — цель, приёмочный порог фиксировать после замера (OD-13).
  - Повтор клавиши поднимает уже открытое окно.
  - Демон не запущен → системное уведомление из скрипта клавиши (Q-74).
- **Клавиши (B35)** — только частые действия (HIG Keyboards):
  - **Alt+W**, **Alt+T**, **Alt+E**, **Ctrl+Alt+P**, **Alt+I** — пять главных (IDEAL II);
  - **Alt+B** — продолжить с места;
  - **Alt+K** — справка.

  Остальное v1 (Alt+C, Alt+G, Alt+L, Alt+F, Alt+S, Alt+Y, Alt+V, Ctrl+Alt+W, Ctrl+Q, Alt+H) — без своих клавиш: доступно через ручной выбор внутри Alt+W и Alt+T, через хаб или убрано.
- **Общие правила окон** (B3, B14–B19):
  - окна ввода забирают клавиатуру, окна показа и появившиеся сами — нет;
  - Esc закрывает всегда; анимация не блокирует ввод;
  - пружинная анимация без отскока; «уменьшить движение» уважается;
  - звук выключен по умолчанию; затемнение вокруг окна (halo) выключено по умолчанию (B33);
  - системная тема и шрифт; акцентный цвет только у главных действий и индикаторов;
  - Ctrl+= / Ctrl+− / Ctrl+0 — масштаб текста (F-99);
  - ответ ИИ: маленький значок «ИИ», цитата-опора там, где есть, [Повторить];
  - ошибки — по F-71; введённый текст не теряется.

#### Alt+W — помочь понять (F-02…F-10)
- Механика выпадает по весам 70/10/10/5/5 (Q-04): 4 слова / объяснение-вопрос / пример / ступенька / «Мужичок» (один постоянный персонаж, Q-11).
- Ручной выбор — кнопками в окне.
- **4 слова:** 4 объекта `{simple, term, meaning}`; кнопка **[Сначала сам]** скрывает ответ ИИ, пока пользователь не впишет свои 4 слова; сравнение — кодом, по основам слов; совпадения подсвечиваются, счёт не показывается (Q-05, Q-06).
- **Предвычисление 4 слов** по выделению — по умолчанию выключено, включается в настройках ИИ (Q-08). Без него окно открывается сразу с текстом «Выбираю 4 опоры из абзаца…».
- **Объяснение:** не больше 4 терминов, до 80 слов каждый, пометка опоры («Из текста.» / «Часть — из текста…» / «Этого в тексте нет…») и «Опора: «…»» (F-07).
- **«Другой ракурс»** — кнопка в окне ответа, без своей клавиши (F-85).

#### Ctrl+Alt+P — гипотеза (F-13, F-14; B21)
- Сначала гипотеза записывается, потом проверяется.
- Ответ короткий и корректирующий: вердикт без оценки личности (без похвалы), что не так, как исправить, цитата из учебного текста. [Подробнее] раскрывает узлы.
- Расплывчатая гипотеза → одна просьба «смелее».
- Опровергнутая гипотеза → единица FSRS (S4, правило 9).

#### Alt+E — заметка (F-12)
- Заметка с якорем-цитатой; закрывается только вручную в хабе (Q-14).

#### Alt+T — практика
- По S5.

#### Alt+I — урок на 15 минут (F-25…F-30; A6, B20, B25)
1. Если есть незавершённый урок → «продолжить» первым (INV-08).
2. **Цель урока** — конкретная достижимая цель на ~15 минут, привязанная к долгосрочной цели Alt+S (B20).
3. **Два пути:** [Сгенерировать] или сначала вписать свои мысли «что надо изучить» → генерация с их учётом.
4. **Вход генерации:** 9 видов контекста (IDEAL IV.2), правила планировщика (S4/F-78: профиль цели, вид умения, `observed` / `assumed`), не больше 1 старого пробела и только если он мешает цели (B21). Обязательных фаз нет (B25).
5. **План** 2–5 пунктов. Пункты менять нельзя, только явно пропускать; можно попросить [Другой план] целиком (B20, B25).
6. Статусы пунктов `pending / current / worked / skipped`; `worked` ≠ освоено.
7. **Часы** 15 минут; ввод «25 разберу X» меняет длину; путь 1 / 3 / 5 / ∞ шагов и звезда (F-26).
8. **Конец шага:** окно появляется само, но не забирает фокус (B14). [Да] [Частично] [Нет] → «что вынес» → «Дальше?».
9. **Конец урока:** «что осталось» → S3 (единицы) → уведомление.
10. Мост «что ты оставил» — только собственные слова пользователя (F-28).
11. **Временные веса механик в уроке:** ×2 для механик, которые обслуживают вид умения цели урока; сброс в конце (Q-03, OD-07).
12. **Программа предмета** (B71): темы курса по порядку; следующую тему для цели урока выбирает код (первая не отмеченная), отмечает тему пройденной только пользователь — в хабе или при закрытии урока.

#### Хаб (F-73)
- Окно из значка в трее, без клавиши.
- Вкладки:
  - «ИИ» — ключ, провайдер, модель, проверка, строка о передаче данных;
  - «Предметы» — Alt+S: долгосрочная цель, срок, программа (B71), 8 видов умений, состояния цели, выключение механик;
  - «Единицы» — список, [Освоил], тип, [Объединить] / [отделить], кандидаты;
  - «История» — гипотезы, заметки, сессии, отчёт MRT.
- Без ключа открывается на вкладке «ИИ».

#### Alt+B — продолжить с места (F-43)
- Firefox, Okular, Obsidian, как в v1.

## 5. Фоновые механизмы

1. **Прерывающие** (Opportunity, Daily) — общий журнал, общий бюджет внимания, без повторов одного «вернись к учёбе» (Q-56 «б»).
   - Не показывать, когда пользователь занят (`slack`: идёт шаг, открыто окно, ждёт ручной запрос) или смотрит видео либо играет.
   - Лимиты v1: ≤ 3 в день, ≥ 2 ч между показами, 24 ч после «Не сейчас».
2. **Тексты карточек** сообщают, а не командуют (HIG; B16): «Есть гипотеза с расхождением» вместо «Воспроизведи…». Без личного содержания; детали — после клика.
3. **Daily** предлагается при создании цели в Alt+S; приходит не по старту ПК, а в первый момент, когда пользователь свободен (Q-59 «д»). Согласие обязательно (INV-09).
4. **Лампочка** — пассивный индикатор; **микроцели** — строка внутри Alt+I; **Director** — источник правил планировщика, отдельных окон не открывает.
5. **MRT** (B12, B13, B34):
   - первый эксперимент по OD-06: точка решения — проверенная ошибка; действие — короткая диагностика или молчание; исход — независимая проверка той же единицы через 1–7 дней; пропуск — `missing`;
   - два раздельных исхода: вовлечённость и проверенный результат;
   - guardrails: отказы, переключения, доля самостоятельных попыток;
   - A/A-проверка до первого вывода;
   - доля молчания и минимум данных — расчётом по журналу;
   - рандомизация — только при осмысленных условиях (B12).

## 6. Данные (OD-11, A17)

- **Новая локальная SQLite.** Модель данных — `docs/v2/DATA_MODEL.md`.
- **Архив v1** только для чтения, в отдельном каталоге. Автоматического переноса нет (A17).
- **Сеть** — только к выбранному провайдеру ИИ.
- **Удаление и экспорт** — явные команды `cp data export`, `cp data delete --all`.
- **Тексты** по сроку не удаляются.
