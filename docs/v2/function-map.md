## Как читать

**Метки статуса в названии функции:**

| Метка | Значение |
|---|---|
| `[v1]` | Есть в коде v1 и переносится по смыслу. |
| `[v1→]` | Есть в v1, но меняется по решениям 26–28.10. |
| `[новое]` | Нет в v1; описано в IDEAL STATE или в обсуждениях. |
| `[заморожено]` | Есть в v1, выключено; переносить только по отдельному решению. |
| `[идея]` | Записано как идея; реализацию не начинать до ответа на открытые вопросы. |

**Правило о числах.** Числа, тексты и пороги со ссылкой «v1: …» взяты из кода. Если конкретики нет ни в коде, ни в решениях, она не придумывается: такой пункт уходит в «Открытые вопросы» функции и в общий список (раздел «Открытые вопросы»), где у каждого вопроса есть номер Q-NN.

**Примеры.** Пользователь в примерах — «пользователь». Учебная тема в примерах — линейная алгебра (метод Гаусса) и Excel (XLOOKUP): эти темы есть в данных v1.

**Хранилище в примерах.** Таблицы v1 названы как в коде: `steps`, `step_journeys`, `notes`, `predictions`, `tasks`, `returns`, `recall_admissions`, `learning_lessons`. Для функций со статусом `[новое]` имена таблиц и полей предлагаемые; они помечены «(предл.)».

**Общий контракт для всех окон** — F-71 (ошибки) и F-69 (одно окно на функцию). В описаниях функций он не повторяется.

## 2. Описание каждой функции

## A. Понимание текста

### F-01. Захват текста `[v1→]`
- **Зачем.** Каждая функция начинается с того, что пользователь выделил; ему не нужно копировать и вставлять вручную.
- **Триггер.** Вызов любой функции с текстом: F-02–F-13, F-17, F-18, F-25.
- **Вход.** Primary selection (Wayland), класс и заголовок активного окна.
- **Логика.**
  1. Прочитать primary selection: `wl-paste --primary --no-newline`.
  2. Если пусто, эмулировать Ctrl+C и прочитать буфер обмена, затем вернуть прежнее содержимое буфера. Восстанавливаются только типы `text/plain;charset=utf-8`, `UTF8_STRING`, `text/plain`, `image/png`.
  3. Если в буфере есть метка `x-kde-passwordManagerHint` (пароль), захват не выполняется.
  4. Определить происхождение текста:
     - `copy` — «из активного окна»;
     - `primary` — «из выделения»;
     - `clipboard` — «из буфера обмена»;
     - `dev` — «из окна разработки · не в учебную историю». Так помечается текст из терминалов (kitty, foot, alacritty, wezterm, ghostty, konsole и другие из списка `TERMINAL_CLASSES`) и редакторов кода (zed, code, codium, pycharm, idea, neovide, emacs).
  5. Если заголовок браузера содержит Claude, ChatGPT, Gemini, Perplexity, DeepSeek, Copilot, Codex или OpenCode, это чат с ИИ, а не учебный текст.
  6. Текст длиннее 12 000 символов для задач обрезается (v1: `MAX_CONTEXT_CHARS = 12000`).
- **Выход.** Невидим. При ошибке — уведомление одной строкой из списка:
  - «Захват пропущен: защищённый буфер обмена»;
  - «Не удалось сохранить прежний формат буфера обмена»;
  - «Источник изменился при захвате — повтори выделение»;
  - «Не удалось отправить команду копирования»;
  - «Копирование не передало выделенный текст».

### F-19. Пробы — «муравьи» `[v1]`
- **Зачем.** Механическая отработка операций на объём, на новых экземплярах (B5, B9). Решение владельца от 22.10: «МЕХАНИЧЕСКАЯ отработка, не опросник».
- **Триггер.** Маршрут «пробы» в F-18; кнопка [Практика и микропробы].
- **Вход.** Текст из F-01.
- **Логика** (исправлено 28.10 по коду `probes.py` и `popup_helper.py`; в первой редакции ассистент описал её неточно).
  1. Модель строит **дерево**. Первая страница — **3 категории (типа)**, по **3 карточки** в каждой.
     - **Категория** — семейство родственных операций с одним `invariant` (смыслом семейства). Название — 2–4 слова. Это не школьный предмет.
     - Категории упорядочены: ближе к главной мысли, заметность малого изменения, применимость вне фрагмента, доступность.
  2. **Карточка** — основная вариация:
     - `action` — какое действие;
     - решённый образец `example.before → example.after`, который всегда виден;
     - ниже числовая подвариация: `prompt` (новый экземпляр для самостоятельного решения) и скрытый `answer`.
  3. **[Ещё 3]** у каждой категории добавляет **3 другие основные вариации этой же категории**, а не числовые копии. Нажимать можно **сколько угодно**; есть страницы и кнопка «назад».
  4. Вид карточки: `numeric`, `substitution`, `contrast`, `grounded`, `order` или `judgment`. Для `judgment` нужна точная цитата `source_span`. Параметры `numeric` и `substitution` подставляются, только если действие от этого не меняется.
  5. **«Шаг поменьше»** — у карточки может быть до 2 более мелких подшагов.
  5a. **Подсказка-кнопка по правилам** (`ProbeGuidance`, правила в коде, без LLM):
     - первый промах → подсвечивается «другой вариант»;
     - повторный промах на той же вариации → «Шаг поменьше»;
     - успех на новом случае → «Ещё 3»;
     - 3 чистые вариации подряд → подсветка снимается.

### F-34. Ядро FSRS `[v1]`
- **Зачем.** Считать сроки повторения только по проверенным ответам.
- **Триггер.** Проверенный ответ в F-21 или F-36.
- **Вход.** Вид доказательства (evidence), время последней самостоятельной проверки.
- **Логика.**
  1. Расчёт — Rust-мост к `fsrs.rs` из Taskathlon (`fsrs_bridge`).
  2. Перевод в оценку (`fsrs-grade-policy.v1`):
     - `verified_incorrect` → Again;
     - `correct_after_help` → Hard;
     - `independent_correct` → Good;
     - Easy не ставится никогда.
  3. «Не помню» → Again; хранится как самоотчёт.
  4. Отметки урока, вердикты модели и самооценки не идут в FSRS (A7).
  5. Самостоятельный повтор засчитывается, только если с прошлого прошло ≥ 24 ч (`MIN_INDEPENDENT_REVIEW_GAP = 86400`).
  6. **Новая версия (B27, B30):**
     - сроки целиком считает FSRS (`desired_retention` 0,9; `learning_steps` 1 мин и 10 мин; `relearning_steps` 10 мин);
     - параметры подбираются по журналу пользователя (`Optimizer`);
     - ручной порог 24 ч пересматривается;
     - оценка — код (`verified`) или сверка с эталоном (`self_graded`): Промахнулся → Again, Частично → Hard, Совпало → Good.
- **Выход.** Невидим.
- **Что сохраняется.** `returns`: `review_kind="fsrs_review"`, `due_epoch`, `status=pending`; состояние карточки FSRS (stability, difficulty).
- **ПРИМЕР.** 30.10 в 10:00 ответ на «integer_roots» проверен кодом, верно, без подсказок → Good. FSRS: следующий срок 03.11 10:00. В базе: `returns.due_epoch = 1762164000`.
- **Крайние случаи.**
  1. Второй верный ответ через 3 ч → не засчитывается как повтор (меньше 24 ч).
  2. Мост не собран (`build-fsrs-bridge.sh` не запускали) → повторения выключены, пилюля скрыта, в журнале ошибка.
  3. Вердикт модели без кода → в FSRS не идёт.

## G. Фоновые механизмы и эксперименты

**Общее правило для блока.** Каждое автоматическое решение записывается в журнал, даже если ничего не показано. Это нужно, чтобы честно сравнивать «показали» и «промолчали» (F-57). Режимы:
- `off` — ничего не решается и не пишется;
- `shadow` — решение пишется, ничего не показывается;
- `experiment` — показывается в части случаев, остальное — контроль;
- `active` — показывается всегда, когда правило сработало.

### F-62. Отрисовка формул `[v1]`

- **Где.** `goal_model.py` (одна модель размечает цель) → `goal_planner.py` (чистые правила, без модели) → Director.
- **Логика.**
  1. Цель → **профиль**:
     - `short_deadline` — диагностика, проверенный повтор, выбор метода, практика;
     - `applied_selection` — выбор метода, различение, диагностика;
     - `long_practice` — практика, различение, выбор метода, возвраты;
     - `deep` — Фейнман, гипотеза, различение, диагностика;
     - `exploration` — гипотеза, Фейнман, практика; очередь повторений только явно;
     - `general`.
  2. Профиль выдаёт порядок предпочтительных действий и **одно локальное умение** с основанием:
     - `observed` — по своим попыткам пользователь видел затруднение;
     - `assumed` — следует только из формулировки цели.
  3. Нет модели, умений или материала → `status=unknown`, план не навязывается.
- **Пример.** «Экзамен по тервер 20.11», осталось 5 дней → `short_deadline`; локальное умение «различать P(A∣B) и P(B∣A)» с основанием `observed` — 3 ошибки в пробах.
- **Крайние случаи.**
  1. Цели нет → `general`.
  2. Цель «из интереса» → в очередь повторений ничего не ставится автоматически.
  3. Попыток нет → основание `assumed`.
- **Критерии готовности.** Если вход одинаковый, то и план одинаковый; LLM в выборе не участвует.
- **Открытые вопросы.** В v1 планировщик подключён к Director (выключен по умолчанию) и к Daily. Подключить его к генерации урока Alt+I (B25)? Это и есть недостающие «правила выбора следующего действия».

### F-79. Диагностическая проба после промаха `[v1]`
- **Зачем.** Один ✗ не значит, что умения нет: это может быть описка или одна подоперация. Одна проверенная задача уточняет.
- **Где.** `diagnostics.py`, без модели.
- **Логика.** Источник по порядку:
  1. подшаг провалившейся карточки → цель — подоперация;
  2. для `numeric` — новый случай той же операции по шаблону → отличить описку от систематической ошибки.

  Если источника нет → `not_eligible`, с причиной; ничего не выдумывается.
- **Пример.** ✗ на «R2 − ⅓R1» → диагностика «вычисли ⅓·6» (подшаг).
- **Крайние случаи.**
  1. Ответ не число → не проверяется.
  2. Подшагов нет и карточка не `numeric` → `not_eligible`.
  3. Диагностика тоже ✗ → затруднение `observed` (F-78).
- **Критерии готовности.** Если источника нет, то задача не создаётся.
- **Открытые вопросы.** Нет.

### F-80. Измерение отсроченного удержания по методам `[v1]`
- **Зачем.** Узнать, какой метод лучше удерживает знания: 4 слова, гипотеза, Фейнман, практика, песок, Initium, свободное припоминание.
- **Где.** `retention.py`, без окон и без модели. Отсроченная проба для материала, пройденного любым методом.
- **Логика.**
  1. Шкала исхода: провал 0 / с колебанием 1 / самостоятельно 2 (самоотчёт).
  2. Вывод — не раньше 8 оценок на метод (`MIN_SCORED_PER_METHOD`).
  3. Сводка читает только хэши, id и время, но не тексты.
- **Пример.** «Гипотеза»: 9 отсроченных проб, средний балл 1,4; «4 слова»: 3 пробы → «данных мало».
- **Крайние случаи.**
  1. < 8 оценок → вывода нет.
  2. Пропуск → `skipped`, не провал.
  3. Самоотчёт — помечен, это не проверка.
- **Критерии готовности.** Если у метода меньше 8 оценок, то в сводке «данных мало».
- **Открытые вопросы.** Связать с MRT (F-57): это та же задача — что реально помогает.

### F-81. Фоновая подготовка практики и превью `[v1]`
- **Зачем.** Подсветка «есть что попробовать» честная, только если за ней уже есть проверенная задача; превью показывает образец без ответа.
- **Где.** `practice.py` (очередь подготовки; стадии: материал → применение → задача → проверка) и `task_preview.py`.
- **Логика.** Сохранённый фрагмент → анализ «есть ли одно маленькое проверяемое действие» → генерация через конвейер задач (F-20) → публикация только после проверки. Статусы: «Ждёт очереди», «Ищу применение по материалу», «Готовлю задачу», «Проверяю условие», «Есть что попробовать», «Пока не найдено подходящее действие», «Подготовка не удалась».
- **Пример.** Сохранён фрагмент о XLOOKUP → через 20 с «Есть что попробовать» → превью «Найди цену товара K-2…».
- **Крайние случаи.**
  1. Материал сменился → «Материал сменился».
  2. Проверка не прошла дважды → «Подготовка не удалась».
  3. Нет ключа ИИ → подготовка не идёт (B18).
- **Критерии готовности.** Если задача не прошла проверку, то подсветки нет.
- **Открытые вопросы.** Фоновая генерация тратит ключ — та же логика, что Q-08 (по умолчанию выключено?).

### F-82. Предметные протоколы `[v1]`
- **Зачем.** Узкая проверка по шагам там, где её можно сделать кодом.
- **Где.** `learning_protocols.py`, `memory_bayes.py` (`bayes.v2`: условное направление → полная вероятность → апостериорная).
- **Логика.** Контракт задаётся до ответа. Если не выполнено предварительное условие, зависимые шаги блокируются. Неверный итог не превращается в «три ошибки». До 2 попыток.
- **Пример.** Задача Байеса: верно P(B∣A), неверно P(B) → апостериорная не оценивается.
- **Крайние случаи.**
  1. Тема не Байес → `protocol=null`.
  2. Объяснение — всегда вердикт модели, не проверка.
  3. Лимит попыток → «Лимит попыток этой задачи достигнут…».
- **Критерии готовности.** Если ошибка в шаге 1, то шаги 2–3 не оцениваются.
- **Открытые вопросы.** Нет.

### F-83. Мгновенный черновик 4 слов без модели `[v1, не подключено]`
- **Зачем.** Черновик 4 понятий за миллисекунды, без ИИ: частота, разнообразие, обозначения, которые текст определяет сам.
- **Где.** `instant_cues.py`. В живом потоке v1 не используется.
- **Пример.** Абзац о ранге → «ранг, строки, ступенчатый, совместность» за 5 мс.
- **Крайние случаи.**
  1. Формулы, испорченные распознаванием, → не восстанавливаются.
  2. Нет `simple` и `meaning` → только термины.
  3. Короткий текст → меньше 4 слов.
- **Критерии готовности.** Работает без сети.
- **Открытые вопросы.** Использовать как вариант без ключа (B18)? Или как подсказку-заготовку в «мои 4 слова»? Здесь есть риск: черновик подскажет ответ раньше попытки (B8).

### F-84. Сравнение своих слов с 4 словами ИИ `[v1, не подключено]`
- **Зачем.** Офлайн-сравнение **эвристического черновика F-83** (не слов пользователя) с сохранёнными опорами модели, без вызова модели. Запуск только вручную: `python -m cognitive_popups.cue_comparison <db>`.
- **Где.** `cue_comparison.py`.
- **Связь.** Алгоритм сравнения (по основам слов) можно переиспользовать для F-04 «мои 4 слова» без LLM (B21). Режима «мои 4 слова» в v1 нет.
- **Пример.** Пользователь: «ранг, строки, нули, ступени»; ИИ: «ранг, преобразования, ступенчатый вид, совместность» → совпадения «ранг», «ступени ~ ступенчатый».
- **Крайние случаи.**
  1. Нет сохранённых опор → сравнивать не с чем.
  2. Разные формы слов → сравнение по основе слова (`stem`).
  3. Пустой ввод → нет сравнения.
- **Критерии готовности.** Если вызывается, то работает без сети.
- **Открытые вопросы.** Нет.

### F-85. «Другой ракурс» (reframe) `[v1]`
- **Зачем.** Одна альтернативная точка зрения на материал (другой организующий принцип).
- **Триггер.** Кнопка после результата гипотезы F-13; действие в окне ответа Alt+C (подсказка клавиши Ctrl+R); пункт меню `reframe`; режим `ask` — с полем «свой ракурс».
- **Логика.** Материал по приоритету: живое выделение → фрагменты последней гипотезы → принятая цель. Если фокуса нет, принцип выбирает модель (`service.reframe`).
- **Выход.** Окно «Другой ракурс». Без материала: «Нет материала: выделите текст или сохраните фрагмент через Alt+W.»
- **Хранение.** Событие `reframe`.
- **Пример.** После «Не подтверждается» по рангу → [Другой ракурс] → «Посмотри на ранг как на размерность пространства строк».
- **Крайние случаи.** Нет материала; ошибка модели (F-71); буфер обмена не считается выделением.
- **Критерии.** Если нажата кнопка после гипотезы, то материал — её фрагменты.
- **Решение (B32).** Оставить как кнопку после результата гипотезы, без своей клавиши (B18). По Янгу — несколько представлений (СМ, гл. 7).
